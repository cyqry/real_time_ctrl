生产配置、生成与覆盖规则

一、灰度一键发布

  双击 publish_gray.cmd

或执行：

  .\scripts\publish_stack.ps1 -Channel Gray

发布后的 Windows 程序位于 deploy\gray\artifacts，可直接双击 EXE，不依赖运行脚本、
证书或配置 sidecar。正式身份与构建输入先运行：

  .\scripts\generate_production_identity.ps1 -ServerAddress ytycc.com
  .\scripts\build_hardened.ps1

生成脚本把随机秘密和 TLS/Noise 身份保存到仓库 deploy 下，并收紧 ACL；构建脚本临时加载
这些值。build.rs 只声明读取规则，实际值由 Cargo 传给 rustc，并经 hidden!(env!(...))
转换为密文数组。发布审计会检查原始值不能在最终二进制中直接搜索到。

三、运行时覆盖

real_ctrl：
  REAL_CTRL_SERVER_HOST
  REAL_CTRL_TLS_PORT
  REAL_CTRL_TLS_SERVER_NAME
  REAL_CTRL_TLS_CA_CERT
  REAL_CTRL_TLS_SERVER_SPKI_SHA256
  REAL_CTRL_AUTH_SECRET
  REAL_CTRL_API_TOKEN
  REAL_CTRL_API_ALLOW_EXEC
  REAL_CTRL_HTTP_LOCK_PATH
  REAL_CTRL_HTTP_BINDING
  REAL_CTRL_HTTP_PORT
  REAL_CTRL_ACCOUNT_ID
  REAL_CTRL_INSTANCE_ID

ctrl_server：
  CTRL_SERVER_BIND_HOST
  CTRL_SERVER_PORT
  CTRL_SERVER_TLS_PORT
  CTRL_SERVER_TLS_CERT
  CTRL_SERVER_TLS_KEY
  CTRL_SERVER_AUTH_SECRET
  CTRL_SERVER_ACCOUNTS_JSON_BASE64
  CTRL_SERVER_KIK_NOISE_PRIVATE_KEY
  CTRL_SERVER_ALLOW_EXEC

通用：
  RUST_LOG
  RUST_BACKTRACE

运行环境变量优先于编译默认值。环境变量指定 TLS 文件路径时使用该文件，否则使用内置 PEM。
这使 EXE/ELF 可以直接运行，也保留无需重新编译的应急轮换能力。

多账号 JSON 先以 UTF-8 编码，再整体 Base64。顶层是账号数组，每项格式如下：

  [{"account_id":"tenant_a","secret":"至少32位ASCII随机值","allowed_kiks":["*"],
    "max_instances":32,"max_commands_per_account":64,"max_commands_per_instance":16}]

`allowed_kiks` 应优先填写允许访问的 Kik UUID；`"*"` 仅适合明确允许全部 Kik 的部署。
real_ctrl 的 `REAL_CTRL_AUTH_SECRET` 必须与所属账号 secret 一致。未配置实例 ID 时，每个进程
自动生成随机 UUID；同机多个 HTTP 实例还必须使用不同端口和锁文件名。

四、安全边界

二进制字符串混淆只阻止 strings/十六进制搜索，不能阻止动态调试、内存转储或控制流分析。
ctrl_kik 仅内置 Noise 公钥，不持有控制认证秘密、API token、TLS 私钥或 Noise 私钥。
real_ctrl 和 ctrl_server 只内置各自运行所必需的值。身份轮换后应重新构建全部关联组件；
紧急情况下可先用运行环境覆盖。

五、固定端口

灰度：ctrl_kik Noise 9005，real_ctrl TLS 9009。
正式：ctrl_kik Noise 9002，real_ctrl TLS 9007。
两个职责端口相同会启动失败。
