# ctrl_kik 受保护发布

## 安全边界

保护目标是移除项目源码路径、调试符号、运行日志和全部发布态业务明文，并启用 Windows PE
缓解属性，从而提高静态分析成本。它不能阻止确定性的反汇编、动态调试或内存提取。

`ctrl_kik` 只内置公开的 Noise X25519 服务端公钥，用它验证对端持钥并加密命令与数据连接。
授权秘密、TLS 私钥和 API token 不进入客户端；授权、审计和限流由管理面承担。

## 字符串规则

- 需要复用或集中修改的非秘密字符串放在 `common/config.json`。`common/build.rs` 使用
  AES-256-GCM 生成密文代码到 Cargo `OUT_DIR`，运行时通过 `OnceLock` 缓存解密结果。
- 一次性错误、响应和进程参数使用 `common::hidden!`。字符串字面量在构建期加密，动态参数
  在运行时追加，例如 `hidden!("连接失败: ", endpoint, ", error=", error)`。
- 禁止写成 `hidden!(format!(...))`，否则内部格式模板仍会作为明文进入 PE。
- 混淆 key 随解密代码进入二进制，只用于阻止直接静态搜索，不能承载任何秘密。

`ctrl_kik/src/screen` 的捕获行为保持不变，但其发布态错误、线程名和后端名同样使用
`hidden!`；测试专用字面量与 `compile_error!` 不进入 Windows 发布 PE。

## 发布入口

完整灰度发布：

```powershell
.\scripts\publish_stack.ps1 -Channel Gray
```

只构建客户端：

```powershell
.\scripts\build_ctrl_kik_protected.ps1 `
    -ServerHost "example.com" `
    -ServerPort 9002 `
    -BuildChannel production `
    -NoiseServerPublicKey "<32 字节 X25519 公钥 Base64>"
```

脚本固定 nightly/rustc commit，使用 `build-std` 重编译标准库，启用
`panic=immediate-abort`、`location-detail=none`、路径重映射、fat LTO、单 codegen unit、CFG、
CET、ASLR、NX 和符号剥离。构建开始即使旧产物与 receipt 失效，避免失败后误发布旧文件。

发布只接受复制到 `deploy/<channel>/artifacts/ctrl_kik.build-receipt.json` 的回执中：

```text
production_ready = true
audit.passed = true
audit.protected_scope_plaintext_clean = true
audit.full_project_plaintext_clean = true
```

具体大小、SHA-256 和 Rust/Tokio 指纹以当次 receipt 为准，不在文档硬编码易过期值。

## 不采用的方案

- 不把 Authenticode 当作防逆向手段；它只能证明发布者和签名后的完整性。
- 不实现反调试、反虚拟机、自修改代码或全程序商业壳，避免杀软误报和稳定性退化。
- 不为了隐藏语言指纹私自分叉 Rust 标准库、Tokio 或安全依赖；上游公开运行时字符串仅做
  数量回归，新增内容需要人工复核。
