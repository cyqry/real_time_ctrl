# ctrl_kik 部署适配说明

更新日期：2026-10-01。

本项目遵循 [Kik 端程序通用规范](../Kik端程序规范.md)。本文只记录 `ctrl_kik` 的具体实现和操作入口，
不把本项目功能作为其他 Kik 程序的必需能力；通用安全、信息量、产物与交付要求不在此重复定义。

## 1. 实现对应

| 通用要求 | 本项目实现 |
| --- | --- |
| 固定公钥持钥验证、认证加密 | 原始 X25519 公钥；命令和数据连接使用 Noise NK |
| 单程序直接运行 | Windows x64 的 `ctrl_kik.exe`；后台子系统，不创建控制台 |
| 管理面授权 | `real_ctrl` API 与 `ctrl_server` 承担账号、权限和审计职责；Exec 双层授权 |
| 会话隔离 | 一条主连接与三条绑定到当前主会话的数据连接 |
| 受控发布构建 | `scripts/build_ctrl_kik_protected.ps1`；protected hardened、固定完整 rustc commit |
| 静态信息与平台审计 | `common::hidden!` / 编译期配置保护、全项目扫描、PE 缓解检查 |

工具链由 `rust-toolchain.toml` 和 `../scripts/ctrl_kik_hardening.psd1` 双重约束；生产构建使用
`--locked`、`--no-default-features` 并重编译标准库。具体保护与审计实现见 [防逆向发布.md](防逆向发布.md)。
通用 `build_hardened.ps1` 不负责 Kik 发布；控制端和服务端的生产诊断符号继续保留。

## 2. 实际协议与业务边界

- Noise 握手不携带业务 payload；固定公钥来自构建输入，不在运行时替换。
- 主连接接收本实例 Kik ID、心跳、当前命令，以及任务能力确认、准备和传输清理消息。
- 数据连接包含当前 Kik ID 确认、随机挑战与绑定确认，随后传输带关联 ID 的业务数据；不能描述为仅返回成功布尔值。
- `task_key` 每个主会话在 Kik 本地随机生成，经加密主连接上行，用于数据连接证明；只存当前会话内存。
- 下载和截图的控制端保存路径发送前移除，保留字段可承载服务端生成的数据 ID。上传只传 Kik 目标路径，不传控制端源文件完整路径。
- 任务 `PrepareNamed` 包含关联 ID、大小、SHA-256、`TaskSpec` 和执行必需的最终文件名，
  通过 `HelloNamed/HelloNamedAck` 握手使用。最终名称取可选 `file_name`，省略时保留二进制原文件名；不再散列名称。
  `TaskSpec` 包含同步/异步、输出方式、超时、参数和默认响应内容。
  启用开关、服务端任务目录、二进制原路径和完整配置文件留在服务端。
- 当前 Kik ID 为进程内状态，同进程重连可复用，不承诺进程重启后保持 ID。
- 服务端不保存被控者选择；PC/App 每条远程请求携带 Kik ID，离线或重连不自动换机。
- 命名任务保留当前约定：目录与配置独立，启动后无任务并行数配额；同步超时终止，异步仅确认启动。
  这不是其他 Kik 程序的任务或资源管理要求，详见 [任务执行.md](../任务执行.md)。

字段和状态机见 [协议说明.md](../协议说明.md)，实现约束见 [AGENTS.md](AGENTS.md)。

## 3. 构建配置与运行文件

| 配置 | 构建变量 |
| --- | --- |
| 主机/IP | `RTC_CTRL_KIK_BUILD_HOST` |
| Noise 端口 | `RTC_CTRL_KIK_BUILD_PORT` |
| 通道 | `RTC_CTRL_KIK_BUILD_CHANNEL` |
| 单实例锁路径 | 仅 `common/config.json` 的 `strings.LOCK_FILE_PATH`，不接受环境覆盖 |
| 服务端公钥 | `RTC_CTRL_KIK_NOISE_SERVER_PUBLIC_KEY` |

这些变量不在运行时覆盖。灰度、正式公钥必须显式注入；复用既有服务端身份，不得静默轮换。

| 通道 | Kik Noise 端口 | 控制端 TLS 端口 |
| --- | ---: | ---: |
| Gray / `gray` | 9005 | 9009 |
| Production / `production` | 9002 | 9007 |

`LOCK_FILE_PATH` 按 `common/config.json` 原值编入程序，发布脚本不替换成 `ctrl_kik.lock`。
绝对路径不随工作目录变化，相同路径的实例互斥；相对路径才相对于进程工作目录解析。运行用户须能创建或打开配置路径。
锁随文件句柄释放，不得删除锁文件强行绕过。此单实例锁与任务缓存目录中的 `.locks` 准备锁用途不同。
自动 E2E 只修改 `target` 下测试源码副本的 `common/config.json`，原配置不变；测试产物不得作为正式 EXE 分发。
归档程序的自动直启/公网脚本先核对回执中的锁路径；若会写项目外路径则明确停止，不能偷偷覆盖配置或删实际锁来通过验收。
大文件接收在系统临时目录使用随机名和 `.temp` 后缀。新版任务程序在 `<系统临时目录>/<部署命名空间>/` 中按配置名或原文件名缓存，不再创建 `rtc-task-cache-v2` 一级目录，
每次核对对应文件 SHA-256 后复用；传输暂存仍随机命名，任务结束保留缓存。同名任务共享准备锁和程序路径，运行期不持锁。
新旧命名规则不得静默互换；先升级服务端再升级 Kik。更新占用、命中及旧缓存清理规则见 [任务执行.md](../任务执行.md)。
任务仅支持原生 Windows `.exe`，保留后缀大小写，不执行脚本。系统临时目录及缓存目录必须由当前用户可信地管理，
不能配置为其他不受信任用户可写的共享目录；目录检查和文件共享保护不替代操作系统 ACL 或用户隔离。

## 4. 产物目录与回执

以下路径相对于仓库根目录：

| 路径 | 用途 |
| --- | --- |
| `target/ctrl-kik-protected/` | 可重建的 protected 中间文件与原始回执 |
| `deploy/<channel>/artifacts/ctrl_kik.exe` | 最终交付 EXE |
| `deploy/<channel>/artifacts/ctrl_kik.build-receipt.json` | 对应审计回执，不是启动依赖 |
| `deploy/<channel>/manifest.json` | 通道、逐组件时间、状态、大小和摘要 |
| `deploy/<channel>/identity/` | 受 ACL 保护的构建/服务端身份，不交付给 Kik |
| `deploy/<channel>/rollback-local/<run-id>/` | 归档替换前的回退副本 |
| `deploy/<channel>/reports/`、`reports/` | 发布与验收证据 |

回执必须匹配实际 EXE，且满足：

```text
profile = hardened-protected
production_ready = true
audit.passed = true
audit.protected_scope_plaintext_clean = true
audit.full_project_plaintext_clean = true
```

`production_ready` 仅表示回执所覆盖的二进制审计通过，不代替通用规范中的完整发布验收。
跳过组件标记 `retained` 并保留原构建时间；新构建标记 `built`。
当前整栈 manifest 的顶层 `target` 记录服务端目标，不能据此认定 Kik 架构。

## 5. 构建与验收入口

在仓库根目录执行：

```powershell
# 仅预览 Kik 构建计划
.\scripts\publish_stack.ps1 -Channel Gray -SkipCtrlServer -SkipRealCtrl -PlanOnly

# 仅构建并归档灰度 Kik
.\scripts\publish_stack.ps1 -Channel Gray -SkipCtrlServer -SkipRealCtrl

# 仅构建并归档正式 Kik
.\scripts\publish_stack.ps1 -Channel Production -SkipCtrlServer -SkipRealCtrl
```

上述单组件构建不要求 Docker 或 SSH，不部署服务端，不自动执行公网验收，也不会替换其他电脑上的 Kik。
完整发布、参数和服务端回滚见 [生产发布与公网验收.md](../生产发布与公网验收.md)。

本项目按变更范围调用以下入口，并保留与最终产物匹配的结果：

| 入口 | 验证范围 |
| --- | --- |
| `scripts/audit_production_dependencies.ps1` | 实际生产依赖审计 |
| `scripts/test_direct_artifacts.ps1` | 归档程序无开发环境配置直启 |
| `scripts/e2e_ctrl_stack.ps1` | 本地协议、授权、并发、文件及目标绑定回归 |
| `scripts/test_public_stack.ps1` | 匹配通道的公网链路验收 |

业务验收覆盖实际支持的命令、文件往返摘要和目标下线不换机；任务变更另验证同步/异步、超时和临时文件边界。
网络与协议变更检查发往 Kik 的真实字段，避免附带控制端本地路径或无关身份信息。
报告明确环境、命令、结果与未覆盖项；本文不复制某次构建摘要、测试数字或性能样本作为长期证明。
